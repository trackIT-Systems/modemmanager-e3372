# Huawei E3372h-153 reference

Findings from bringing up the E3372h-153 with ModemManager. Verified on
the stock HiLink firmware `22.329.63.00.21` (WebUI
`WEBUI_17.100.20.03.03_HILINK`), hardware `CL2E3372HM Ver.A`, on a
Raspberry Pi 5. The [README](../README.md) covers installation and the port
layout; this document covers the rest.

## USB modes

| USB ID | Mode | How it gets there |
|---|---|---|
| `12d1:1f01` | Storage (virtual CD-ROM) | After power-on or a firmware reboot |
| `12d1:14dc` (usual ID, not checked on this stick) | HiLink: the stick is a router with NAT at `192.168.8.1`, `cdc_ether` | HuaweiNew message (`usb_modeswitch -J`), what usb-modeswitch-data sends |
| `12d1:155e` | Modem: AT ports and NCM | HuaweiAlt message (`usb_modeswitch -X`, `HuaweiAltMode=1`), what this package sends |

The storage and modem mode IDs are the same as on the E3372h-320, and the
package's `/etc/usb_modeswitch.d/12d1:1f01` switches both. The switch isn't
stored; the stick comes back as `12d1:1f01` after every power cycle or
firmware reboot.

The -153 can also be reflashed to "stick" firmware (`21.x`), which comes up
as `12d1:1506` without a mode switch. That isn't needed: the HiLink firmware
runs in modem mode after the HuaweiAlt message.

## Modem mode interfaces

| If | Class | Function | Driver | ModemManager |
|---|---|---|---|---|
| 0 | `ff/ff/ff` | AT / PPP | `option` (`ttyUSB0`) | secondary AT port |
| 1 | `ff/ff/ff` | Diagnostics | `option` (`ttyUSB1`) | not used ("unhandled port type") |
| 2 | `ff/ff/ff` | AT | `option` (`ttyUSB2`) | primary port |
| 3 | `02/0d/00` | NCM control | `cdc_ncm` (`wwan0`) | data port |
| 4 | `0a/00/01` | NCM data | `cdc_ncm` | – |

Unlike on the E3372h-320, all serial interfaces are `ff/ff/ff`, and the port
types come from `^GETPORTMODE`, which this firmware supports:

```
^GETPORTMODE: TYPE: WCDMA: huawei,,3g_modem:0,3g_diag:1,pcui:2,ncm:3
```

The kernel binds `option` and `cdc_ncm` by itself; no extra udev rules are
needed.

## Data connection

ModemManager's Huawei plugin dials with `^NDISDUP` and reads the address from
`^DHCP?`; NetworkManager configures `wwan0` statically (e.g.
`10.0.90.114/30`, gateway `10.0.90.113`). ModemManager reports IPv4 as the
only supported IP type, so the bearer is IPv4 only (the -320 also does
IPv4v6).

Like the -320, the stick keeps an NDIS connection active when ModemManager
goes away without disconnecting; patch 0004 disconnects it before the next
dial (verified with SIGKILL, see the README's Status section).

Patches 0001–0003 aren't needed for the -153: Debian's Huawei plugin handles
it the same way, including the extended signal values, although `^HCSQ?`
answers with a bare `OK` as on the E3372-325.

## AT commands

| Command | Response |
|---|---|
| `^DIALMODE?` | `^DIALMODE:2,3` (same as the -320) |
| `^GETPORTMODE` | Port list, see above |
| `^SETPORT?`, `^SETPORT=?` | `ERROR` (no switchable USB composition on the HiLink firmware) |
| `^HCSQ?` | Bare `OK`; the values come unsolicited |
| `+CESQ` | `ERROR` |
| `^VERSION?` | Firmware, WebUI and hardware version |

Interface 1 (diagnostics) doesn't answer AT commands. `AT^RESET` on an AT port
reboots the firmware.
